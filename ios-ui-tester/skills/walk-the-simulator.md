# Walking the app in the simulator

## The matrix

- List every screen or flow step the task names, numbered in the order you walk them. For each, the devices: the one the task names, or the one a script it names picks (read which device type and runtime that script picks on this host, and create your own of the same; where the host has none, choose one and say so), else one current iPhone on the newest installed runtime, said as your choice; and both appearances, `light` and `dark`, unless the task names one. {#list-steps-devices-appearances}
- One screenshot per cell: step × device × appearance, plus each state the task cares about (empty, loading, error, long content, signed out, a larger Dynamic Type size). {#one-shot-per-cell}
- Name each file so it says its cell: `<nn>-<step>-<device>-<appearance>[-<state>].png`. {#file-names-its-cell}
- Before walking, look in the evidence path for a walk already there: where its note names the commit you walk, look at its shots, keep the cells they cover and walk only the gaps; a walk of another commit is walked again. {#reuse-a-prior-walk}

## A device of your own

- Create a fresh device per device type, named for the task (`xcrun simctl create <task>-<device> <device type> <runtime>`; `xcrun simctl list devicetypes runtimes` names them), and address it by the UDID create prints, never `booted`, which may be someone else's. A missing runtime is a question to the foreman; install none. {#create-own-device}
- Boot it before you build or write any walk script, and wait until it is up (`xcrun simctl bootstatus <udid> -b`), never a fixed sleep. A fresh device that will not boot (a CoreSimulator or audio service error) fails so on every device of that host: ask the foreman with `guild task question`, naming the host and the error, and end your turn; never retry it or build on. {#boot-and-wait}
- Fix what would differ between runs before the first shot: `xcrun simctl status_bar <udid> override --time 9:41 --batteryState charged --batteryLevel 100 --cellularBars 4 --wifiBars 3`, and the locale the task names, English otherwise. {#fix-the-status-bar}
- Set the appearance with `xcrun simctl ui <udid> appearance light|dark`, then relaunch the app (`xcrun simctl terminate`, `launch`) so every screen draws in it; Dynamic Type with `xcrun simctl ui <udid> content_size <size>`. {#set-the-appearance}
- Install and launch the built app (`xcrun simctl install <udid> <App>.app`, `xcrun simctl launch <udid> <bundle id>`), and capture what the app says beside what it shows: its log while you walk (`xcrun simctl spawn <udid> log stream --predicate 'subsystem == "<bundle id>"'` into scratch), and whether it crashed (a launch that returns no pid, or a crash report in `~/Library/Logs/DiagnosticReports` named for the app). {#install-launch-capture}

## Reaching each screen

- Shoot with `xcrun simctl io <udid> screenshot <file>` once the screen is settled: its content drawn, no spinner, animations ended; wait on the app's log or the element, or take the shot again until two in a row match, never a fixed sleep alone. A sheet, menu or system sheet (share, Files) takes seconds to present, so give it a long settle; a keyboard or search field left open hides toolbar buttons, so dismiss it before you go on; a UI test's shot caught mid-fade is taken again with `simctl io`. {#shoot-when-settled}
- Reach a screen the way the app already offers: a deep link it declares (`xcrun simctl openurl <udid> <url>`), a launch argument or environment it documents (`xcrun simctl launch <udid> <id> -<arg>`), taps on what is on screen with AXe (simctl cannot tap; an external tool, `brew install cameroncooke/axe/axe`, then `axe tap --id <id> --udid <udid>`, `axe type <text> --udid <udid>`), or its own XCUITest target run against your device: `xcodebuild build-for-testing` once in the scratch copy, then `xcodebuild test-without-building -destination 'platform=iOS Simulator,id=<udid>' -only-testing:<target>/<test> -resultBundlePath <scratch>/r.xcresult`, its screenshots exported with `xcrun xcresulttool export attachments --path <scratch>/r.xcresult --output-path <dir>`, whose `manifest.json` names each shot and its time. {#reach-the-app-s-way}
- Find an element by what the accessibility tree shows (`axe describe-ui --udid <udid>`, or a UI test's hierarchy attachment): by identifier, else by label, since a screen's identifier can override its child's and another device type can draw the same control differently (tabs as buttons, not a tab bar); never by coordinates guessed from a picture. {#find-by-the-tree}
- Where none of these reaches a screen, a short UI test of your own in the scratch copy may, never committed, its shots attached with `lifetime = .keepAlways` so a passing test keeps them; the app's own UI test that fails on your device is reported in the note, and patched only in the scratch copy. A screen still unreached is named as not seen, and how you tried. {#unreached-is-not-seen}
- Where a step would send, buy, delete or sign in with a real account, stop before it and say so in the note; the simulator walk uses no credential of anyone's. {#stop-before-real-actions}
- When a step fails or the app crashes, keep the shot of where it stopped and the log lines around it; relaunch and go on with the other cells. {#keep-the-failed-step}
