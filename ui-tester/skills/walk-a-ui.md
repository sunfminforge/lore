# Walking a UI

## The matrix

- List every page or flow step the task names, numbered in the order you walk them. For each, the widths (default 375, 768 and 1280 CSS pixels when the task names none, and say that you chose them) and the color schemes (`light`, `dark`; both when the task names none). {#list-steps-widths-schemes}
- One screenshot per cell: step × width × scheme, plus each state the task cares about (empty, loading, error, long content, signed out). {#one-shot-per-cell}
- Name each file so it says its cell: `<nn>-<step>-<width>-<scheme>[-<state>].png`. {#file-names-its-cell}
- Where the task asks for a recording, record each width × scheme as one video of the whole walk (Playwright's `recordVideo` on the context, its `size` set to the viewport, since by default it scales down to fit 800×800), and note at what time each step starts; the video is written only when `context.close()` is awaited. Take the shots as well unless the task says the recording alone. {#record-when-asked}

## Driving the browser

- Use what the repo already uses (its Playwright config, its test server, its fixtures) read-only; otherwise a Playwright script of your own in your scratch space: `npm install playwright-core` there (it downloads no browser) and launch the system Google Chrome (`channel: 'chrome'`). Install nothing outside your worktree or scratch space; a missing Chrome or node is a question to the foreman. {#use-the-repos-tools}
- Headless, a fresh context per cell: reach the width by `viewport`, never by window size (headless Chrome will not size a window below about 500px), and check `window.innerWidth` equals it; set `colorScheme` to the scheme, a fixed locale, timezone and device scale factor, and `reducedMotion: 'reduce'`, so runs compare. Where a page shows the time or a relative date, fix it with `page.clock.setFixedTime(...)` before `goto` on fixtures, and name that time in the note; on a live service, note the time instead. {#fresh-context-per-cell}
- Wait for the page to settle on what it shows, never on the network and never a fixed sleep: `goto` with the default `load`, then wait for the element the cell is about (`locator.waitFor()`) and `document.fonts.ready`. `networkidle` is discouraged by Playwright and never comes on a page that polls or holds a socket open. {#wait-until-settled}
- Shoot with `animations: 'disabled'` and the mouse moved off the page (`page.mouse.move(-1, -1)`), so a transition or a hover is not caught half done; full-page unless the task asks for the viewport. {#shoot-still}
- Reach each flow step the way a user would, by user-facing locators (`getByRole`, `getByLabel`, `getByText`); CSS or XPath only where the page offers no name, and said so in the note. A step whose element does not appear within the timeout is a failed step, not a reason to guess another selector. {#step-by-role}
- Capture what the page says beside what it shows, read by the script in each cell: console errors, failed requests, the HTTP status, horizontal overflow at the width (`scrollWidth > clientWidth`), the links' hrefs, the page title, and where words matter, the page's text as its accessibility tree (`page.locator('body').ariaSnapshot()`) saved beside the shot as `<shot name>.aria.yml`. It has no `mask`: a field the shot masks still reads in it, so take it of a locator that leaves the field out, or leave it out (skills/hand-in-evidence.md). {#capture-page-signals}
- When a step fails, keep the shot of where it stopped and the error; go on with the other cells. {#keep-the-failed-step}

## Fixtures and live services

- On fixtures, record which fixture and which build (commit, or version) you walked: the one the task names, a pull request's head, not an earlier build; shots of an older build are walked again. Build from a scratch copy of that commit (`git archive <commit> | tar -x -C <scratch>`), its dependencies installed the lockfile's way (`npm ci`, `cargo build --locked`), and serve it the way the repo documents, on `127.0.0.1` only; where the walk needs a source edited (a live-reload serve), edit the copy. Change nothing to make it start: a UI that will not build or start is a finding, the command, its exit code and the last lines of its log. {#fixtures-walk-the-named-build}
- On a live service, record its URL and the time. Use only the read-only credential you were handed, passed by the environment, never written in a script, a URL or a file. Take no step that changes data: no submit, save, delete, send, purchase or settings change. Where the task asks for a flow past such a step, stop before it and say so. {#live-changes-no-data}
- Prefer a session that cannot write: a read-only account or token, or the signed-out view. If the credential you were given could write, say so in the note and touch only what reads. {#prefer-a-read-only-session}
