# Reasoning a first feature set

A first feature set is the smallest set a first version could ship that is
worth choosing over the apps surveyed. Reason it from the findings, not
from what you would like to build.

- Table stakes go in, as few as the category's users expect of every app, each citing the finding that shows nearly every app has it. {#table-stakes}
- Add one or two features that answer a complaint that comes back across apps, or a gap none fills; these are why someone would switch, and each cites its finding. {#answer-a-complaint}
- For each feature, one line on what it does for the user, in your own words, never another app's name for it. {#say-it-in-your-words}
- What you leave out of the first version, list with the reason: too costly for a first version, served by few, or answering no finding. {#what-is-left-out}
- Mark what is your judgement as yours: the survey says what is, the feature set argues what to build, and the decision is not yours; open questions for whoever decides go last. {#judgement-is-marked}

Done when every feature cites a numbered finding of the survey, and every
finding about a shared complaint or a gap is either answered by a feature
or set aside with a reason.
